## 1. Refactorización de DTOs

### Objetivo
Ajustar todos los DTOs para que coincidan con las entidades actualizadas.

### Cambios realizados

| DTO | Cambio |
|-----|--------|
| `UsuarioRequestDTO` / `UsuarioResponseDTO` | Separados para Request/Response |
| `ProductoDTO` | Usa `BigDecimal` en precios |
| `IngredienteDTO` | Usa enum `UnidadMedida` |
| `RecetaDTO` / `DetalleRecetaDTO` | Usa `BigDecimal` |
| `VentaDTO` / `DetalleVentaDTO` | Usa `BigDecimal`, cantidad como `Double` |
| `CompraDTO` / `DetalleCompraDTO` | Usa `BigDecimal`, incluye `ingredienteId`/`productoId` |
| `MovimientoStockDTO` | Usa `BigDecimal`, agrega `cierreDiaId` |
| `InventarioRegistroDTO` | Nuevo para `InventarioRegistro` |
| `InventarioDetalleDTO` | Nuevo para `InventarioDetalle` |
| `InventarioItemDTO` / `InventarioReporteDTO` | Recreados para inventario |
| `ClienteDTO` | Nuevo |
| `InventarioDTO` | Recreado para reportes dashboard |

### Eliminados
- `CompraDetalleDTO` (duplicado de `DetalleCompraDTO`)
- `InventarioDTO`, `InventarioReporteDTO`, `InventarioItemDTO` (reemplazados)

## 2. Mappers MapStruct

Todos los mappers fueron ajustados:

```java
// Ejemplo: DetalleRecetaMapper
@Mapping(target = "recetaId", expression = "java(detalleReceta.getReceta() != null ? detalleReceta.getReceta().getId() : null)")
@Mapping(target = "ingredienteUnidadMedida", expression = "java(detalleReceta.getIngrediente() != null ? detalleReceta.getIngrediente().getUnidadMedida().name() : null)")
DetalleRecetaDTO toDTO(DetalleReceta detalleReceta);
```

**Reglas aplicadas:**
- `toEntity()` ignora relaciones y IDs auto-generados
- `toDTO()` mapea IDs y nombres de relaciones anidadas
- Usa `expression` para manejar nulos de forma segura

## 5. Controller REST API

### EmpresaController
- Anotado con `@RestController`
- Endpoints en `/api/v1/empresas`
- Retorna `ResponseEntity<T>`
- Usa `@ControllerAdvice` para manejo de excepciones global

### Endpoints

| Método | Endpoint | Descripción |
|--------|----------|-------------|
| GET | `/api/v1/empresas` | Lista todas |
| GET | `/api/v1/empresas/{id}` | Busca por ID |
| GET | `/api/v1/empresas/subdominio/{subdominio}` | Busca por subdominio |
| POST | `/api/v1/empresas` | Crea empresa |
| PUT | `/api/v1/empresas/{id}` | Actualiza empresa |
| DELETE | `/api/v1/empresas/{id}` | Elimina (desactiva) |
| POST | `/api/v1/empresas/{id}/activar` | Activa empresa |
| POST | `/api/v1/empresas/{id}/desactivar` | Desactiva empresa |

### Códigos HTTP
- `200 OK` - Éxito
- `201 CREATED` - Creación exitosa
- `204 NO_CONTENT` - Eliminación exitosa
- `400 BAD_REQUEST` - Datos inválidos
- `404 NOT_FOUND` - Recurso no encontrado

## Consideraciones Técnicas

### Patrón DTO
- **Entrada:** DTO → Service (validaciones) → Mapper → Entidad
- **Salida:** Entidad → Mapper → DTO → ResponseEntity

### Separación de Responsabilidades
- **Controller:** recibe requests, retorna responses
- **Service:** lógica de negocio, validaciones
- **Repository:** acceso a datos
- **Mapper:** conversión DTO ↔ Entidad

### Manejo de Errores
- Excepciones de negocio lanzadas en Service
- `@ControllerAdvice` global captura y retorna códigos HTTP apropiados
- Controller limpio, sin try-catch

### Testing
- Tests unitarios con Mockito
- Datos de prueba en DataProvider estático
- JUnit 5 puro (sin AssertJ)
